SETUP SCRIPT. Run it when the user asks to install, set up or add the DevOps team to a project. Call the tools yourself; ask the user only where a step says ask.

1. Call detect_project. Tell the user the languages and services found and what is already installed (cursor, claude, profile, gitignoreOk).
2. Languages and services: use what the user named. Otherwise use the detected ones and ask once whether to add or drop any, and whether they want Docker, a cloud, an AI service (Claude, GPT, Gemini, Ollama) or a VM set up. Any language works for any purpose. A language that is not listed: call get_language on a similar one, draft an entry, call add_language with apply=false and show it.
3. If the devops_brief tool is available, this is Claude Code with the plugin installed: it supplies the skill, agents, commands and MCP server, so pass target=none (only .devops/ and the thought folders are written; the person can also type /devops setup claude). Call install_devops_team with apply=false (target defaults to auto: the host folders that exist, else both). If the project already has an equivalent rule file, pass skipRules. Show the user what would be created, replaced and skipped, and any warnings.
4. Ask whether the team should share the profile and standards in git (shareConfig=true commits .devops/; default keeps everything local). Ask for agreement. On yes call install_devops_team with apply=true. Nothing the install writes is committed: the tools (devops-skill/kit/), thought files, the copies in .claude/ and .cursor/ and, by default, .devops/ go into .git/info/exclude, so no tracked file changes. If status then shows gitignoreOk=false call ensure_gitignore with apply=true. If the report says git already tracks some of those files (an earlier install), show the git rm --cached command it gives; never run it yourself. Thought files go in devops-skill/thoughts/non-final/ and devops-skill/thoughts/final/.
5. Call check_toolchain for the chosen language and service ids. List what is missing with the install lines from get_language / get_service. Never install software or run the project's own commands yourself; use sandbox_plan to show how a command would run in the sandbox.
6. On request only: config_get / config_set (project standards: line length, limits, lint rules; set plans first, apply only after the user agrees), ghas_plan (GitHub security files), tag_history / tag_plan (releases), module_map / reuse_search (research), story_new / story_graph (stories), cleanup_scan (cleanup).
7. Finish: tell the user to fill in the "Fill in by hand" section of .devops/project.md. Nothing needs committing; with shareConfig, commit .devops/ only. Without the plugin (target is not none), to connect the project's own server: `node devops-skill/kit/scripts/devops-setup.mjs connect --dest .` (or init from the clone did it already). With the plugin, skip this: it supplies the server.

Rules: plan before writing; write only after the user agrees; existing files are kept unless the user says replace; environment variables are named, never valued; nothing is pushed.
